# context-keeper 模板

下面每个示例上方标注的是文件路径，不是文件内容。所有指向文档的路径都从仓库根写起。

## 指针

注释、rule、CLAUDE.md 里指向文档的那一行：**重点 + 什么时候读 + 仓库根起的路径**，括号里可以写文档里有什么。

```text
<重点>。<什么时候>读 <仓库根起的路径>（<文档里有什么>）
```

- 重点：文档里不知道就会做错的结论（坑、约束、已知限制）必须写；文档里没有这类结论的（纯历史、纯数据）才省掉
- 什么时候：写成动作，"改 X 前""要调 Y 时""评估 Z 前"
- 不写 `原因见 X`、`详见 X`、`见文档`
- 领域索引 rule、文档入口里的登记行也按这个格式写

## 代码注释

只和一个文件（或其中一段代码）有关的，写在相关代码上方，1–3 行。两三行能说完的直接写，不拆文档。`apps/web/src/api/client.ts`：

```ts
// 拦截器的注册顺序不能换：鉴权头要在签名之前补上，否则签名对不上，请求全部 401
export function setupInterceptors() {
```

约束调用方的（改这个文件的人不用知道、调用它的人要知道）不写成普通注释，写进 API 文档注释：

```ts
/** 必须在 setupInterceptors() 之后调用：拦截器里会补上鉴权头，顺序反了首个请求 401 */
export function createClient() {
```

有扩展内容时，注释留重点和指针，扩展内容进文档。改造前，`apps/web/src/api/retry.ts`：

```ts
// 重试次数固定为 3。以前是 5 次，但上游网关连续 5 次失败
// 会把客户端 IP 拉黑 10 分钟，线上出过一次事故。
// 首次 + 3 次重试 = 4 次，留一次余量。
// 试过在网关前加熔断，和网关限流叠加后导致长时间不可用，放弃了。
// 退避从 200ms 起指数增长。
const MAX_RETRY = 3;
```

改造后：

```ts
// 重试上限 3：网关连续 5 次失败会封 IP 10 分钟。改重试次数或退避前读 apps/web/.context/api/retry-policy.md（事故经过、试过的熔断方案）
const MAX_RETRY = 3;
```

"退避从 200ms 起指数增长"读代码就能看出来，删掉。涉及整个文件的写在文件头注释里。

## rule

只给**几个文件共用**的内容，或没法写注释的文件（JSON、lockfile、生成物、二进制资源）用。只和一个能写注释的文件有关的，写成注释。

**frontmatter 的 `---` 必须是文件第一行**，前面不能有任何内容（包括注释和空行）。正文"做什么"在前，一两句原因跟在后面，不超过 10 行（不算 frontmatter 和空行）。

包内 rule，glob 相对该包写。文件 `apps/web/.claude/rules/styling/tokens.md`：

```markdown
---
paths:
  - "src/styles/tokens/*.css"
---

改这里的 token 后必须跑 `pnpm tokens:build`，否则 `src/styles/generated/` 不会更新，但页面不报错。
```

有扩展内容时，rule 留"做什么"和指针。根作用域的 rule（单仓库的所有 rule，或 monorepo 的跨包 rule），glob 从仓库根写完整路径。文件 `.claude/rules/db/schema-web-sync.md`：

```markdown
---
paths:
  - "packages/schema/src/tables/*.ts"
  - "apps/web/src/generated/db/*.ts"
---

改 schema 后必须跑 `pnpm db:generate` 重新生成 apps/web 的类型，生成物不能手改。要改生成逻辑或排查类型对不上时读 .context/db/generated-types.md（生成流程、试过的方案）
```

## 领域索引 rule

给**能挂到代码上、但不属于某一处**的文档用（外部系统调研、领域内几处共用的数据）。已被注释或 rule 里的指针指到的文档不用再登记进来。每个有这类文档的领域一个，文件名固定为 `context-index.md`，`paths` 覆盖这个领域的代码。文件 `apps/web/.claude/rules/api/context-index.md`：

```markdown
---
paths:
  - "src/api/**"
  - "src/hooks/useRequest.ts"
---

api 相关的项目文档。每行前半句是重点，细节按需读：
- 网关单 IP 每秒 50 次，连续 5 次失败封 IP 10 分钟。改请求频率、重试、超时前读 `apps/web/.context/api/upstream-gateway.md`（封禁的计算口径、各接口实测延迟）
- 401 只刷新一次 token，并发的请求等同一次刷新，不各刷各的。改登录态刷新、401 处理前读 `.context/auth-session-flow.md`（时序、试过的方案）
- 新增或改动错误码映射前读 `apps/web/.context/api/error-codes.md`（各错误码的来源和含义）
```

每份文档一行：重点 + 什么时候读 + 仓库根起的路径。

- 重点是文档里不知道就会做错的结论。只有路径和"什么时候读"的登记行，Claude 要读完整份文档才拿得到重点，rule 加载进来等于什么都没给。
- 只写结论，经过、数字、表格留在文档里，不抄进来。会变的当前值（已用多少、当前体积）也留在文档里：登记行里的重点过时了没有 hook 提醒。
- 文档里没有这类结论的（纯参考，如上面最后一行）才省掉重点，这时以"什么时候读"开头，不以路径开头。
- 重点一句话写不完（一份文档有好几条结论）的，不进索引，单独写成一条 rule：正文是这几条结论加指针。

## 文档入口

给**挂不到代码上**的文档用（评估过但没做的需求、外部系统限制、还没有代码的决定）。每个有这类文档的作用域一个，固定为 `<作用域>/.context/README.md`，并由根 CLAUDE.md 指过来（见「CLAUDE.md 索引小节」）。文件 `apps/web/.context/README.md`：

```markdown
# 项目文档入口

挂不到具体代码上的项目文档。做新需求、评估方案前，先看有没有相关的。每行前半句是结论，细节按需读：
- 分期付款 2026-08 评估过，没做：现用的支付渠道只对企业商户开放分期接口。要做分期付款、或评估换支付渠道前读 `apps/web/.context/payment/installments.md`（什么条件变了值得重新评估）
- 现用的 SSO 服务商最多配 5 个回调域名。接入新的登录方式前读 `apps/web/.context/sso-provider-limits.md`（已用几个、各配给了谁）
- 安装包上限 50MB。新功能要引入依赖、二进制或大资源时读 `apps/web/.context/build/package-size.md`（当前体积、各依赖占多少、历次实测）

只在改代码时才用得上的文档由各领域的 `.claude/rules/<领域>/context-index.md` 在碰到相关代码时带出来，不在这里列。
```

格式和领域索引一样，每份文档一行：重点 + 什么时候读 + 路径。最后一行是"两边都登记"的例子：`package-size.md` 同时登记在 `build` 的领域索引里，两处各写各的重点和"什么时候该读"。

和领域索引不一样的一处：入口里的文档挂不到代码上，重点一句话写不完时没有 rule 可拆，也不从入口里拿掉。登记行写评估需求时最容易做错的那一条，括号里点出文档里还有哪几条结论。

## 文档

没有固定模板，写什么、怎么分节按内容定。约束：

- 第一行是标题，说清这份文档讲的是什么主题
- 写现状，不按日期追加段落，情况变了就原地改
- 有条件成立的内容，在对应段落开头写明适用条件（如"仅 macOS："）
- 同一指标的多次实测用表格，新值追加一行，不覆盖旧值：

  ```markdown
  | 日期 | 改动 | 数值 | 测法 |
  |---|---|---|---|
  | 2026-09-05 | 引入路由级懒加载前 | 2.4s | Lighthouse 移动端 |
  | 2026-09-20 | 引入路由级懒加载后 | 1.1s | Lighthouse 移动端 |
  ```

能挂到代码上的长背景，示例文件 `apps/web/.context/api/upstream-gateway.md`（登记进 `api` 的领域索引 rule）：

```markdown
# 上游网关的限制

## 限流与封禁

- 单 IP 每秒 50 次，超出返回 429
- 连续 5 次失败（5xx 或超时）封禁客户端 IP 10 分钟，期间所有请求返回 403
- 封禁按出口 IP 算，同一机房的实例共用额度

## 接口延迟

| 日期 | 接口 | p95 | 测法 |
|---|---|---|---|
| 2026-08-12 | /orders | 380ms | 线上 APM 7 天数据 |
| 2026-10-03 | /orders | 210ms | 线上 APM 7 天数据（网关升级后） |
```

挂不到代码上的，示例文件 `apps/web/.context/payment/installments.md`（登记进 `apps/web/.context/README.md`）：

```markdown
# 分期付款

2026-08 评估过，没做：现用的支付渠道只对企业商户开放分期接口，我们是个人商户，升级要重新走资质审核（约 2 个月）。

值得重新评估的条件：账户升级为企业商户，或换了支付渠道。
```

文档只写背景。能挂到代码上的"做什么"写在原处（注释或 rule），原处留指针。

## skill

```markdown
---
name: release
description: 发布到生产环境。当用户要求发布、上线、打 tag 时使用。
---

# 发布

1. <步骤>
2. <步骤>
```

description 要写清"什么时候用"，它是启动时唯一常驻的部分。

## CLAUDE.md 索引小节

根 CLAUDE.md 末尾：

```markdown
## 更多上下文
- 各包和各模块的专属约定、背景会按路径通过 rule 自动加载，不用手动查
- 做新需求、评估方案前，先看 `.context/README.md` 和 `apps/web/.context/README.md`：评估过但没做的需求、外部系统限制、还没有代码的决定
- 记下读代码看不出来的项目知识（原因、踩坑、实测数字、外部约束）：只涉及一个文件的写成紧贴代码的短注释，几个文件共用的写进 `.claude/rules/`；经过、数字等扩展内容和挂不到代码上的写进 `.context/`，原处留「重点 + 什么时候读 + 路径」（装了 context-keeper 插件就用 `record-context`）。不写成长注释，也不只记在自动记忆里；改动让已有注释、rule 或 `.context/` 文档里的说法不再成立时，同一次改动里改掉
- 发布流程：用 `/release`
```

- 第二行（文档入口）列出**所有作用域**里存在的 `.context/README.md`，没有任何入口时省掉这一行。
- 第三行是常驻的写入约定，**不要省**：没有它，Claude 会按默认习惯把背景写进注释或自动记忆。
- 单仓库去掉"各包"的说法。
- 索引里只列根作用域的 skill：包内 skill 要碰到该包的文件后才可用，名字也带目录前缀，写进根索引会指向一个调不到的命令。
