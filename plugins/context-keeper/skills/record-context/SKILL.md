# 记录上下文

下面是日常记录够用的全部规则。碰到这里没覆盖的情况（判断形态、目录级 CLAUDE.md、敏感信息清单等），读 `${CLAUDE_PLUGIN_ROOT}/references/layout.md` 对应一节；要新建文件时照 `${CLAUDE_PLUGIN_ROOT}/references/templates.md` 的模板写。

## 1. 值不值得记

**同时满足**两条才记：

- **本次会话真正验证过**：实际跑过、读代码确认过、或用户明确说的。不记推测。
- **下次会重新踩**：读一遍代码就知道的不记；"这次做了什么、改了哪些文件"不记，那是 commit 的职责。值得记的是：为什么非这么做不可、试过什么不行、实测出来的数字、外部系统的限制、碰到某些文件时必须注意的事。commit message 里写过也照样记——Claude 平时不翻 git 历史。

一次任务最多记三条，想记的更多说明在记流水账，挑最重要的三条。不确定就问用户。

被 comment-hook 提醒有长注释块而来的：注释里的背景过不了上面两条的，不建文档，直接把注释删掉或缩到 1–3 行；过得了的照下面走，拆注释不占“最多三条”。

## 2. 属不属于项目

- 个人偏好、对你的纠正、个人习惯 → 不进仓库，写自动记忆。用户想对所有项目生效时，给一行可粘贴到 `~/.claude/CLAUDE.md` 的文本，不直接改那个文件。
- 换台电脑、换个网络就不成立的（本机路径、本机版本、端口、代理、凭据） → 不进仓库，写自动记忆。
- 有条件成立的（"仅 macOS""Node 20 以下"） → 属于项目，正文第一行写明条件。
- 含 API key、token、密码、内网地址、私有仓库地址、带用户名的绝对路径等敏感信息 → 一律不进仓库。

属于项目的知识**不要只记进自动记忆**：那里只对你自己这台机器生效，队友和其他 worktree 看不到。

## 3. 写成什么

先把这条拆成两部分：**必须知道的那一句**（做什么、坑，加一句原因）和**扩展内容**（经过、试过的方案、数字、更多原因）。整条两三行就说完的不拆。

必须知道的那一句，按顺序问，第一个"是"就停：

1. 能用 lint / CI / hook 自动校验吗？能 → 建议用户加检查，但**不停**，照常往下走把文字写好。文字本次不删：告诉用户检查落地后可以自己删掉这条，或下次跑 organize-context 时由体检列出来
2. 是有步骤、平时用不上的流程吗？是 → **skill**：`.claude/skills/<name>/SKILL.md`，description 写清什么时候用
3. 只在碰到特定文件 / 目录时才需要知道吗？是 →
   - 适用于某个包内任何任务（monorepo），或某个已有目录级 CLAUDE.md 所在目录内任何任务 → 写一行进那个包或目录的 CLAUDE.md（包还没有 CLAUDE.md 就新建；不为此新建目录级 CLAUDE.md），不写成覆盖整个包 / 目录的宽 rule
   - 只涉及**一个文件**、且这个文件能写注释 → **代码注释**，写在相关的函数、常量上方，涉及整个文件的写在文件头，1–3 行
   - 涉及**多个文件**（一类文件的约定、一个目录的坑、"改 A 必须同步 B"），或文件没法写注释（JSON、lockfile、生成物、二进制资源）→ **rule**：`.claude/rules/<领域>/<name>.md`，带 `paths`，"做什么"在前，一两句原因跟在后面，正文不超过 10 行
   - "涉及几个文件"按**谁需要知道**算：约束的是调用方的（"必须在 X 之后调用"），涉及的是调用它的那些文件。调用方分散 → 写进定义处的 API 文档注释（JSDoc / docstring）；调用方集中在某个目录 → `paths` 覆盖调用方的 rule
4. 是背景（原因、经过、数字、外部约束、评估过但没做的需求），但挂不到具体代码上吗？是 → **文档**：`context-docs/<领域>/<slug>.md`，登记进 `context-docs/README.md`
5. 剩下的是任何任务都可能违反的硬约束 → **根 CLAUDE.md**（`CLAUDE.md` 或 `.claude/CLAUDE.md`，哪个已存在写哪个），只写一行，不带原因

扩展内容进文档，原处留指针（见第 7 节）。

## 4. 写到哪个作用域

- 单仓库：一律仓库根的 `.claude/`、`context-docs/`。
- monorepo（判断信号见 layout.md「判断形态」）：涉及的文件全在某个包内 → 该包的 `.claude/`、`context-docs/`；涉及两个及以上包 → 仓库根。
- 往 `.claude/` 或 `context-docs/` 新建文件之前，对每个要新建的路径跑 `git check-ignore -q "<路径>"`（如 `apps/web/.claude/rules/api/retry.md`、`context-docs/payment/installments.md`）：退出码为 0 表示会被 `.gitignore` 忽略，写进去队友也看不到，停下来告诉用户。不少项目会把 `.claude/` 整个忽略，别只查 `context-docs/`。`context-docs/` 已被别的用途占用（里面有被代码或工具读取的文件）时同样停下。
- 动手写之前先跑一次检查脚本留基线（见第 10 节）。

**领域**（`<领域>`）取项目已有叫法：先看同作用域 `.claude/rules/` 下已有的领域目录名，其次用代码里的模块名、目录名，不自造。说不清属于哪块、或跨两块以上的文档放 `context-docs/` 顶层。第一份文档就放进领域目录。

**文件名**用 `<slug>.md`，英文小写短横线概括主题（`retry-policy`），不带日期、不带编号。

## 5. 先查重

`ls` 目标目录，再按 slug 和主题关键词 grep **整个仓库**的 `.claude/`、`context-docs/`（`.claude/` 显式传路径，点开头的目录有些工具默认跳过）和所有 CLAUDE.md。有同主题的就**改那份**，让它描述现状（情况变了原地改写，不追加"更新：……"，不改文件名）；它在别的作用域、而这次的内容让归属变了的，照样改那份，并告诉用户，挪动交给 organize-context。不挪动、不改名已有文件。

**改动让已记下的内容过时**（改了指针提到的数值、换掉了文档里写的方案、去掉了 rule 约束的那段代码）：不用过第 1 节的筛，也不占"最多三条"，在同一次改动里把原处的重点和文档改成现状，文档登记在领域索引 rule 或 `context-docs/README.md` 里的，登记行的重点一并改（改完文档 `doc-hook` 会列出指到它的行；hook 没提醒时 grep 文档路径找）；文档整份不再成立的，连同指向它的指针一起删（先在整个仓库 grep 它的路径）。

## 6. 写注释和 rule 时

注释：

- 紧贴相关代码，1–3 行。只改注释行，不动任何可执行代码。
- 涉及整个文件的写在文件头，和下面的代码之间空一行（后面紧跟 import 的不用）：紧贴着第一个声明的注释，`pointer-guard` 会当成那个声明的注释，只在改它时才拦。
- 讲"这段代码在做什么、怎么用"的注释不归本 skill 管，照常写。

rule：

- frontmatter 的 `---` 必须是第一行。
- `paths` 相对 rule 所属作用域的根写（包内 rule 相对包目录），要窄，至少匹配到一个现存文件。只匹配到一个能写注释的文件时，改写成注释。
- 正文"做什么"在前，一两句原因跟在后面，不超过 10 行（不算 frontmatter 和空行）。

## 7. 扩展内容和指针

扩展内容写进 `context-docs/<领域>/<slug>.md`，原处（注释、rule 或 CLAUDE.md 那一行）留指针。这几种情况要拆：

- 注释超过 3 行，或要讲经过、试过的方案、数字
- rule 正文会超过 10 行
- 实测数字和它的历史（原处可以写当前值）
- 同一段背景要被几处共用

指针是一行：**重点 + 什么时候读 + 仓库根起的路径**，可以在括号里写文档里有什么：

```ts
// 重试上限 3：网关连续 5 次失败会封 IP 10 分钟。改重试次数或退避前读 apps/web/context-docs/api/retry-policy.md（事故经过、试过的熔断方案）
```

- 重点：文档里不知道就会做错的结论（坑、约束、已知限制）必须写，写成照着做就不会出错的话。只有路径和触发条件的指针，Claude 得读完整份文档才拿得到重点，等于没拆。文档里没有这类结论的（纯历史、纯数据）才省掉。
- 什么时候读：写成动作（"改 X 前""要调 Y 时"），不写成"原因见 X""详见 X"。
- 路径：纯文本写仓库根起的路径；在 Markdown 里用链接时，链接目标写所在文件起的相对路径（`apps/monitor/CLAUDE.md` 里写 `[重试策略](context-docs/api/retry-policy.md)`，`apps/monitor/.claude/rules/api/context-index.md` 里写 `[重试策略](../../../context-docs/api/retry-policy.md)`），写成仓库根起的路径在 GitHub、IDE 里点不开。
- 指针放在离代码最近的地方：函数 / 常量上方的注释 > 文件头注释 > rule > CLAUDE.md。改代码时 `pointer-guard` hook 只认注释里的指针。

## 8. 写文档时

- 第一行是标题。写现状，不写流水账。
- 实测数字带日期和测法；同一指标的新值追加一行，不覆盖旧值（表格见模板）。
- 评估过但没做的需求：写明卡在哪、评估时间、什么条件变了值得重新评估。
- **登记进入口**，每份文档一行，按第 7 节的指针格式写「重点 + 什么时候读 + 仓库根起的路径」。不登记的文档以后基本不会被读到；登记行只有路径和"什么时候读"的，入口进了 context 也什么都没给。判断办法：不读文档、只看这一行会不会做错？会，就把不做错所需的结论写进这一行，经过、实测数字和会变的当前值（已用多少、当前体积）留在文档里；约束本身的阈值（"每秒 50 次""上限 50MB"）是结论的一部分，写在登记行里。改已有文档让登记行的重点不再成立时，同一次改动里把登记行也改掉：
  - 从某处拆出来的（第 7 节）→ 原处的指针就算登记，不用另建索引。不属于某一处、而是整个领域改代码时都该知道的长背景（外部系统调研、领域内几处共用的实测数据）→ 领域索引 rule `<作用域>/.claude/rules/<领域>/context-index.md`。还没有就照模板新建，`paths` 覆盖这个领域的代码（如 `src/api/**`，不能宽到 `src/**`）。重点一句话写不完（有好几条结论）的，不进索引，单独写成一条 rule：正文是这几条结论加指针。顶层的跨领域文档，登记进每个相关领域的索引。
  - 挂不到代码上的 → 文档入口 `<作用域>/context-docs/README.md`。还没有就照模板新建，并确认根 CLAUDE.md 的「更多上下文」里有一行列出了它的路径（见第 9 节）。这类文档重点一句话写不完时没有 rule 可拆：登记行写评估需求时最容易做错的那一条，括号里点出文档里还有哪几条结论。
  - 改代码时和评估新需求时都要看到的（安装包体积、性能预算、外部系统配额，或某模块评估过但没做的功能）→ 两边都登记，各写各的重点和"什么时候该读"。只在改代码时用得上的不进 `context-docs/README.md`。

## 9. 补 CLAUDE.md 的指路

根 CLAUDE.md 末尾的「更多上下文」索引（模板见 templates.md）：

- 缺「写入约定」那一行时补上。
- 有任何作用域的 `context-docs/README.md` 时，「文档入口」那一行要列出所有这些路径，缺的补上。

根 CLAUDE.md 指 `CLAUDE.md` 或 `.claude/CLAUDE.md`，哪个已存在改哪个；两个都在时改 `CLAUDE.md`。两个都没有时，新建一个只含这个索引的 `CLAUDE.md`。

## 10. 写完之后

1. **写入前**先跑一次 `node "${CLAUDE_PLUGIN_ROOT}/scripts/check.mjs" "<作用域路径>"`（仓库根作用域不传路径）记下结果作为基线，**写完后**再跑一次。脚本以退出码 2 报「路径不存在」「路径不在仓库内」时是路径传错了，改正后重跑，不要当成 `node` 不可用。基线里没有的就是本次引入的（`paths` 匹配不到、rule 过长、单文件 rule、指针失效、指针没写什么时候读、登记行没有重点、孤儿文档、入口没被 CLAUDE.md 指到、`.claude/` 或 `context-docs/` 被忽略等），修掉。例外：脚本报「只匹配一个文件」、而那个文件是生成物或写了注释会被工具覆盖的，rule 是对的，保留，在回复里说明一句。基线里就有的不在这次处理，提醒用户跑 organize-context。`node` 不可用就跳过。
2. 在回复末尾用一行告诉用户写到了哪些文件（含顺带改的入口、CLAUDE.md），例如：

   > 记了一条：`apps/web/src/api/retry.ts` 的注释，扩展内容在 `apps/web/context-docs/api/retry-policy.md`

   > 记了一条：`apps/web/.claude/rules/styling/tokens.md`

   > 记了一条：`apps/web/context-docs/payment/installments.md`（已登记进 `apps/web/context-docs/README.md`）

不要静默写入，否则这套结构会重新变成没人看的黑箱。

## 不要做的事

- 同一件事写进两个地方
- 用 `@path` import 引用文件
- 改 `~/.claude/CLAUDE.md`、`~/.claude/settings.json`
